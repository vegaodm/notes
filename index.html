Notes & Ideas Privacy Policy

This policy explains how Notes & Ideas handles note and tag content on your iPhone or iPad.

Version: 1.0 (Build 1) Minimum system: iOS 17.0 Effective date: September 25, 2026
Local by default Notes and tags are stored in local app data on your device.
No active networking The current version has no accounts, cloud sync, analytics, ads, or tracking.
You control files The app reads or writes a file only when you choose an import or export action.

1. Scope

This policy applies to the Notes & Ideas iOS app. The current app is a local note-taking tool for creating, editing, searching, previewing, pinning, restoring, and deleting notes, with tags used to organize content.

This policy describes the behavior of the current app version. Device backups, the system file picker, and its underlying file providers may be handled by Apple or by a service you choose, and are outside the app's full control.

2. Data Stored and Processed by the App

To provide note-taking features, the app stores the following content locally on your device:

  • Note titles, note content, creation dates, update dates, and unique identifiers;
  • Note pinned status, deletion status, and tag relationships;
  • Tag names, normalized names, creation dates, and unique identifiers.

Search terms, filters, and the Preview zoom level are interface state and are not currently written as separate records in app data. The app does not require an account, create a user profile, or ask for a name, email address, or other identity information.

Local first: The current source code and features do not include a process for sending note content to a server. The app has no account login, cloud sync, online search, advertising, analytics, or cross-app tracking.

3. Import, Export, and Backups

The app accesses a file only when you actively use an import or export feature and select a file. File operations are handled by the iOS system file picker.

Feature Format Data scope
Full data export JSONL (.jsonl) All notes, tags, and note metadata, including notes in Trash.
Full data import JSONL (.jsonl) Imports as a merge; local records missing from the backup are not automatically deleted.
Single-note export JSON The current note and its assigned tags, which may include editor content that has not been saved yet.
Single-note import JSON Loads into the editor for review first; it is written to local data only after you save.

Exported JSON and JSONL files are readable app data files and may contain note content in plain text. Keep them in a location you trust, and do not send sensitive backups to unrelated people. The app validates the format and version of imported files, but it cannot decide whether their contents are appropriate for you to import.

4. Permissions and External Files

The current app does not use the camera, microphone, location, photo library, or contacts, and does not request those permissions. It accesses only the specific file you select when you start an import or export.

If a file comes from iCloud Drive or another system file provider, that provider and the operating system may control its storage, synchronization, and access. Manage the sharing, synchronization, and deletion settings for those files as needed.

5. Data Retention and Deletion

  • Deleting a regular note first moves it to Trash, where its content remains in local data.
  • Restoring from Trash returns the note to the regular note collection.
  • Delete Forever is the action that requests permanent deletion; it cannot be undone.
  • Uninstalling the app, deleting its app container, or deleting an exported file may affect the corresponding data. iOS device backup behavior is managed by the operating system.

The app does not provide a secure-erasure guarantee, so it cannot promise that deleted data is immediately unrecoverable from underlying storage. Use full data export for important content and keep exported files yourself.

6. Security

The app does not provide account passwords, a separate app lock, or end-to-end encryption. Use your device's lock screen, encryption, and backup protections, and avoid leaving sensitive exports in an insecure location.

If a device is lost, damaged, or unlocked by someone else, a person who can access the device or its files may be able to read app data or exported files.

7. Policy Updates

This policy may change when app features, data handling, or supported systems change. The updated version and effective date will be shown at the top of this page. Continued use of the app means that you should review the updated policy.

8. Contact

If you have questions about this policy, local data, or exported files, contact the developer at vegaodm@outlook.com. Please include the app version and your device system version when reporting a privacy concern.
